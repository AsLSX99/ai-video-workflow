# ai-video-workflow

> 用 **Codex + Seedance** 从一个想法做出完整 AI 视频的八步全流程 —— 一个可直接安装的 Finch Skill。

方法论源自 Eian 的实战文章 [《Claude code/Codex+Seedance AI视频：从一个想法到成片的全流程》](https://x.com/EianLu/article/2118317430665613741)。本仓库在保留原文全部流程与提示词的基础上，把总导演从 Claude 换成 **Codex**：写故事、写分镜、写提示词、画设定图与首尾帧、写后期代码，一个入口全包，不依赖任何国内访问不到的服务。

**这个 Skill 解决的问题**：从想法到成片中间的坑——模型配合、剧情构思、画面构图、机位摆放、镜头运动、提示词写法、视频抽卡。核心目标一句话：**用尽量少的钱、尽量低的抽卡率，做出一条自己满意的 AI 视频。**

## 它做什么

触发后，Skill 引导你按固定顺序走完一支片子的完整生命周期，每一关都有独立审核，上一关"通过"才进下一关：

```
想法 ──► 完整剧情 ──► 分镜表 ──► 画风+设定图 ──► 每镜首尾帧
              │           │            │              │
           审核①       色块确认      你确认画风      8项检查
              ▼           ▼            ▼              ▼
        七段式视频提示词 ──► 提交前审核② ──► Seedance 生成
                                                  │
        全片复核④ ◄── ffmpeg 后期 ◄───────────────┘
              │
              ▼
        经验沉淀存档（画风/提示词/错误清单，下一部片直接复用）
```

## 核心原则

**把错误挡在花钱之前。** 成本阶梯决定了所有工作顺序：

| 出错层级 | 修复成本 |
|---|---|
| 提示词里发现 | 改几个字，几乎免费 |
| 图上发现 | 重画一张图，不额外花钱 |
| 视频里发现 | 按秒重新付钱（Seedance 2.5 约 ¥1.5/秒，2.0 mini 约 ¥0.5/秒，720p） |

所以：**能在文字里发现的错，不留到图上；能在图上发现的错，不留到视频上。**

另一个低抽卡率的秘密是**独立审核会话**：主会话和你聊了很久，知道你想说什么，看材料会自动脑补；新开的审核会话什么都不知，只拿当前关卡的材料、不拿任何结论——哪里看不懂，就说明哪里真的没讲清楚。原文作者用这套方法抓出过"两张图杯子大小差 13%、帽檐一张有一张没有、左右写反"这类问题。

## 安装

Skill 发现机制遵循 Finch 的标准目录约定，放在任意一个支持的位置即可：

| 作用域 | 路径 | 说明 |
|---|---|---|
| 项目 / Space | `<项目>/.finch/skills/ai-video-workflow/` | 只在该项目中可用（默认推荐） |
| 用户全局 | `~/.finch/skills/ai-video-workflow/` | 你在本机的所有会话可用 |
| 机器全局 | `~/.finch/skills/`（全局目录） | 这台机器上所有会话可用 |

手动安装就是把本仓库放进上述任一位置：

```bash
# 示例：装到某个项目的 .finch/skills/ 下
git clone https://github.com/AsLSX99/ai-video-workflow.git <项目>/.finch/skills/ai-video-workflow
```

同名 Skill 存在多份时，优先级：当前 Space / 已授权目录 > 当前项目 > 用户全局 > 机器全局。`SKILL.md` 必须直接位于 `ai-video-workflow/` 文件夹内。

## 环境准备

| 依赖 | 用途 | 获取方式 |
|---|---|---|
| **Codex** | 总导演 + 画师（写故事/提示词/画图/写后期代码） | `npm install -g @openai/codex`，然后 `codex login` |
| **ffmpeg** | 第 7 步拼接、转场、调色、放大 | `winget install Gyan.FFmpeg`（Windows）或 `brew install ffmpeg`（macOS） |
| **Python ≥ 3.9** | 运行自检与 Seedance 调用脚本 | python.org |
| **ARK_API_KEY** | Seedance 视频生成 | 火山引擎 → 火山方舟 → API Key |

安装后跑一次自检：

```bash
python scripts/env_check.py
```

全绿输出 `PASS，可以开工`；缺项会逐条给出补齐命令。

`ARK_API_KEY` 写入环境变量（**不要写进任何会提交的文件**）：

```bash
# Windows（写入用户环境变量，重开终端生效）
setx ARK_API_KEY "你的key"

# macOS / Linux
echo 'export ARK_API_KEY="你的key"' >> ~/.zshrc && source ~/.zshrc
```

## 快速开始

1. 建一个项目文件夹，把本 Skill 装进去（见[安装](#安装)）
2. 跑 `python scripts/env_check.py`，补齐缺项
3. 在 Finch 里说 **"做 AI 视频"** / **"Seedance 流程"** / **"想做个视频但不知道从哪开始"**，Skill 触发
4. 把 `templates/00-director.md` 全文发给 Codex 开启项目——它会先问你片长、画幅、总预算、要不要配乐字幕，再自检环境
5. 之后全程只和它沟通，按八步走到成片

## 八步流程

每步标注：做什么 → 用哪个模板 → 过关条件。

### 第 1 步：想法 → 完整剧情
把初步想法讲给 Codex，一起聊到故事定稿。**故事结构首选片段式**（镜头之间不用接戏，最稳），连贯式最容易穿帮。好故事 5 条标准：

1. **符合现实逻辑**——每个转折追问：为什么会这样？东西从哪来？够得着吗？
2. **一句话能说清想表达什么**——自己都说不出来，剧情就太平淡
3. **开头就抓人**——最抓眼球的画面放前面，写清第几秒出现什么
4. **旁人反应像真人**——每个转折分 3 段：问题 → 主角怎么解决 → 旁人什么反应；反应必须有先后，几个人同一秒举手一看就是假的
5. **画面 AI 拍得出来**——避开弱点清单：人物交叉、手拿小东西、文字、镜子倒影、左右不对称、一镜内换光、一人连做三个动作、俯拍看不到脸、配角太多

模板：`templates/01-story.md`。**过关**：新开审核会话用 `templates/02-story-review.md` 审，拿到"通过"。

### 第 2 步：分镜（前期最重要，构图配色比剧情还重要）
每镜写清：片中时间、生成秒数（向上取整多留 0.5 秒）、景别、机位、运镜、谁往哪走（写画面左右）、靠什么表情推进、什么在动、怎么转下一镜。6 条硬要求：

1. 每镜换角度，平视正面全片最多 2 次，其余用俯拍、仰拍、从背后、过肩、透过东西拍
2. 画面里一直有东西在动——人走出走进、飘过的纸、身后路人；固定机位更要让人从远处走到近处
3. 全身 / 半身 / 特写换着来，别连着几个镜头一样大小
4. 每镜至少一样东西在动（摄影机、焦点、光线、前景、人物小动作），该动则动该静则静
5. 运镜要有理由：跟着东西走 / 慢慢推近给特写 / 由近慢慢拉远
6. 黄金比例构图：头或眼睛落在画面左起约 **38%** 或 **62%** 处，别放正中

配色单独设计、列每场色表；画面转黑白检查，人和背景区分不开就重新调配色。有参考片就让 Codex 逐帧量机位和进出画比例再模仿。模板：`templates/03-storyboard.md`。**过关**：色块草图总表（1920×1080 标 38%/62%）给你确认。

### 第 3 步：定画风，画设定图
有参考图最好，直接给。Codex 写提示词 + 自己画，你只看风格对不对。每个角色和固定道具一张设定图：正面、侧面、几个表情，固定特征写死位置（纹身在左手臂上），否则后面每张图都不一样。**过关**：你确认画风，才允许画正式镜头。

### 第 4 步：出每镜首尾帧（降低抽卡率最关键的一步）
顺序很关键：

1. 先让 AI 写出每镜"首帧画什么、尾帧画什么、中间发生什么"，审核通过再画（省额度）
2. 先画内容最多的尾帧 → 在尾帧上改出首帧，保证机位构图一致
3. 同地点同机位直接局部改，不重新画
4. 推近镜头：把首帧裁一块放大当尾帧——首尾构图完全一样等于没推近
5. 检查 16:9 且首尾尺寸一致

雨、帽子、纹身这类小物件必须首帧尾帧都画上，只写文字拍着拍着就没了。画完用 `templates/04-frame-check.md` 逐条检查 8 项。**过关**：8 项全过，你同意后才改图。

### 第 5 步：写视频提示词，提交前审核
固定**七段式**：【画风】【镜头】【构图与配色】【人物】【逐秒】【声音】【约束】，把每一秒发生什么都写下来。模板：`templates/05-video-prompt.md`。写之前对照 `references/pitfall-table.md` 的 **20 条易错点**——出问题先怀疑提示词，再怀疑模型。**过关**：每段提交前新开审核会话用 `templates/06-pre-submit-review.md` 核对每个细节，写"通过"才提交，报价你同意才花钱。

### 第 6 步：生成视频
用 `scripts/seedance.py` 提交（720p 首尾帧模式），轮询取回片段。省钱技巧见[下方专节](#省钱与降抽卡率要点)。出问题的处理顺序：①能不能剪掉（问题只在开头/结尾几帧）→ ②能不能用代码修 → ③才重拍，且先改提示词或首尾帧再拍，只拍这一镜。**旧片段一律不删**，最后新旧一起挑。**过关**：你看过动态、听过声音。

### 第 7 步：拼接、转场、调色、放大
全部用代码做，Codex 写 ffmpeg/Python 脚本。模板：`templates/07-postprocess.md`：转场运动模糊切 8–16 份半帧快门；只调彩度亮度不动色相；BT.601 解码、中间无损、交付标 BT.709；lanczos 放大 1080p 加轻微锐化；卡点只从原曲测拍点。做完抽查切点前后 3 帧。

### 第 8 步：全片复核和交付
新开审核会话，只给成片不给任何结论，让它像第一次看片的观众从头看一遍（`templates/08-final-review.md`）。最后让 Codex 写总结存档：画风、提示词、犯过的错误，沉淀进项目文件夹，下一部片直接复用。

## 省钱与降抽卡率要点

**省钱**
- 720p 生成，后期 lanczos 放大到 1080p
- 不拍测试片，直接拍第一个正式镜头，能用就赚了
- 新做法：先拿一两个最难的镜头试，行得通再全部提交
- 预算紧用 `doubao-seedance-2-0-mini-260615`（约 ¥0.5/秒）；2.5（约 ¥1.5/秒）是它 3 倍价，非复杂镜头 mini 够用
- 声音听过再用：2.0 mini 自带音效常能直接用；2.5 写了"没有音乐"也常混进音乐
- 额度用完等恢复，不充值、不一次同时画太多张

**降抽卡率**
- 首尾帧是命门：先文字审 → 尾帧改首帧 → 叠图查错位 → 尺寸对齐 16:9
- 提交前独立审核必过，逐字核对提示词与图片细节
- 七段式逐秒写，写之前过一遍 20 条易错表
- 出问题先剪、再代码修、最后才改稿重拍

## 常见问题

**Q：没有 Claude，只有 Codex，流程会打折吗？**
原文的分工表里 Claude 本来就是可替换的导演位（原文原话：如果你就是 Codex，就用你自己的生图工具）。本 Skill 直接以 Codex 为导演 + 画师，10 段提示词一字未改，流程完整。

**Q：审核为什么要"新开会话"？**
主会话知道你的全部上下文，看材料会替你脑补；独立会话像第一次看片的观众，哪里看不懂就说明哪里真没讲清楚。这是抽卡率低的核心机制，不要省。

**Q：Seedance 请求格式在哪查？**
火山方舟官方文档《内容生成》章节；或直接用 `scripts/seedance.py`，它已封装提交 / 轮询 / 下载：

```bash
python scripts/seedance.py \
  --prompt 03-prompts/shot01.txt \
  --first 02-frames/shot01_first.png \
  --last 02-frames/shot01_last.png \
  --duration 5 --resolution 720p --out 04-videos

# 查询已有任务
python scripts/seedance.py --task <task_id>
```

**Q：四线程模式什么时候用？**
日常小片用单审核会话（02 / 06 / 08 三个关卡）够了；大预算或长片再上 `09-four-threads.md`，多一个监督管要求清单、一个代理管预算审批。
